# US-04 — Подтверждение специалистом записи в personal bot (MVP)

## Цель
Дать specialist возможность обработать новую запись в личном боте:
- подтвердить запись,
- отклонить запись,
- при отклонении выбрать путь:
  - отклонить с пояснением,
  - отклонить без пояснений,
- автоматически уведомить клиента о результате.

---

## Акторы
- specialist
- personal specialist_bot
- backend
- client
- Google Calendar API

---

## Preconditions
- запись создана по US-03
- `booking_state = awaiting_specialist_confirmation`
- событие уже создано в Google Calendar (`gcal_event_id` сохранён)
- слот уже удерживается Google событием на этапе ожидания подтверждения специалистом

---

## Общие правила (MVP)
- Подтверждение специалистом возможно только из состояния `awaiting_specialist_confirmation`.
- Любая попытка обработать запись в другом состоянии должна завершаться сообщением «Запись уже обработана» и без изменений в БД.
- При отклонении запись становится недоступной для подтверждения специалистом и повторного отклонения.
- При отклонении Google событие удаляется (если существует), чтобы освободить слот.
- После любого решения specialist клиент получает уведомление в личный бот.

---

## C4.1 Входящее уведомление specialist о новой записи

**backend**
1. После создания записи в US-03 публикует outbox-событие `appointment_awaiting_specialist_confirmation`.
2. Отправляет specialist сообщение с карточкой записи:
   - дата/время,
   - имя/идентификация клиента,
   - статус: `Ожидает подтверждение специалистом`.
3. Показывает inline-кнопки:
   - `Подтвердить`
   - `Отклонить`

---

## C4.2 Подтверждение специалистом

**specialist**
- Нажимает `Подтвердить`.

**backend**
1. Повторно читает запись по `appointment_id`.
2. Проверяет текущее состояние:
   - если `booking_state != awaiting_specialist_confirmation`, возвращает «Запись уже обработана».
3. Если состояние валидно:
   - переводит `booking_state = confirmed`;
   - пишет audit-запись действия specialist.
4. Отправляет уведомления:
   - specialist: `Запись подтверждена`;
   - client: `Ваша запись подтверждена специалистом.`

**Результат**
- запись активна в `confirmed`;
- слот остаётся занятым (Google событие сохраняется).

---

## C4.3 Отклонение специалистом — выбор варианта

**specialist**
- Нажимает `Отклонить`.

**backend/UI**
1. Проверяет, что запись всё ещё в `awaiting_specialist_confirmation`.
2. Показывает экран выбора:
   - `Отклонить с пояснением`
   - `Отклонить без пояснений`
   - `Назад`

---

## C4.4 Отклонение с пояснением

**specialist**
1. Выбирает `Отклонить с пояснением`.
2. Отправляет текст пояснения (короткая причина).

**backend**
1. Повторно валидирует состояние `awaiting_specialist_confirmation`.
2. Переводит запись в `booking_state = rejected_by_specialist`.
3. Сохраняет `specialist_rejection_reason`.
4. Удаляет событие из Google Calendar (если `gcal_event_id` существует).
5. Отправляет уведомления:
   - specialist: `Запись отклонена. Пояснение сохранено.`
   - client: `Запись отклонена специалистом. Причина: <пояснение специалиста>.`

**Результат**
- запись отклонена;
- слот освобождён после удаления Google события;
- подтверждение специалистом после отклонения недоступно.

---

## C4.5 Отклонение без пояснений

**specialist**
- Выбирает `Отклонить без пояснений`.

**backend**
1. Повторно валидирует состояние `awaiting_specialist_confirmation`.
2. Переводит запись в `booking_state = rejected_by_specialist`.
3. Фиксирует, что пояснение отсутствует.
4. Удаляет событие из Google Calendar (если `gcal_event_id` существует).
5. Отправляет уведомления:
   - specialist: `Запись отклонена без пояснений.`
   - client: `Запись отклонена специалистом.`

**Результат**
- запись отклонена;
- слот освобождён после удаления Google события;
- подтверждение специалистом после отклонения недоступно.

---

## C4.6 Защита от гонок и повторных нажатий

- Если specialist нажал `Подтвердить` или `Отклонить` повторно по уже обработанной записи:
  - backend не меняет состояние,
  - backend возвращает нейтральный ответ `Запись уже обработана`.
- Если решение specialist пришло после client-отмены или иного терминального состояния:
  - переход запрещён,
  - клиенту повторные уведомления не отправляются.

---

## Ограничения MVP
- Нет шаблонов причин отклонения (только свободный текст или без текста).
- Нет автопредложения альтернативных слотов клиенту при отклонении.
- Нет SLA-таймера автопринятия/автоотклонения.
