# Admin Console Access Runbook

## 1. Scope

Admin Console — внутренний интерфейс. Он **не публикуется во внешний интернет** и не должен иметь публичный routing.

Доступ к `/admin` и `/admin/*` выполняется только через SSH tunnel к backend на `127.0.0.1:8000`.

---

## 2. Где хранится `ADMIN_API_KEY` в production

В production значение `ADMIN_API_KEY` задаётся в серверном env-файле backend, например:

- `/etc/zumbot/backend.env`

> Не добавляйте реальное значение ключа в документацию, чаты, тикеты или скриншоты.

---

## 3. Пошаговый доступ

### Шаг 1. [Локально] Создать SSH tunnel до VPS

Запустите на локальной машине:

```bash
ssh -N -L 18000:127.0.0.1:8000 <user>@<vps-host>
```

Что это делает:
- локальный порт `18000` пробрасывается на `127.0.0.1:8000` на VPS;
- пока команда запущена, локальные запросы к `http://127.0.0.1:18000` попадут в backend на сервере.

### Шаг 2. [Локально] Проверить `/admin` (HTML)

```bash
curl -i \
  -H 'X-API-Key: <ADMIN_API_KEY>' \
  'http://127.0.0.1:18000/admin'
```

### Шаг 3. [Локально] Проверить последние логи

```bash
curl -i \
  -H 'X-API-Key: <ADMIN_API_KEY>' \
  'http://127.0.0.1:18000/admin/logs?limit=5'
```

### Шаг 4. [Локально] Проверить heartbeats

```bash
curl -i \
  -H 'X-API-Key: <ADMIN_API_KEY>' \
  'http://127.0.0.1:18000/admin/heartbeats?limit=5'
```

---

## 4. Security notes

- Не логируйте `ADMIN_API_KEY` и не передавайте его в shell history/shared logs.
- Не вставляйте реальный ключ в скриншоты, записи экрана, баг-репорты и публичные каналы.
- Для демонстраций используйте только плейсхолдер `<ADMIN_API_KEY>`.
