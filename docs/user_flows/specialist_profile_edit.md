# User flow: редактирование профиля специалиста

## Статус
Рабочий flow: форма `/profile/edit` подключена к приватному API и поддерживает сохранение блоков и загрузку медиа.

## Цель
Дать специалисту безопасную точку входа из личного Telegram-бота на web-страницу редактирования профиля и сохранить draft-данные.

## Поток
1. Специалист открывает экран настроек личного бота (блок «Базовые настройки уже применены… Хотите изменить их сейчас?») и нажимает кнопку **«✏️ Редактировать профиль специалиста»**.
2. Бот генерирует `web_connect_token` через существующий сервис web-connect.
3. Бот формирует URL вида `/profile/edit#token=<raw_token>` и открывает страницу сайта.
4. Страница читает token из hash-фрагмента URL.
5. Frontend вызывает backend endpoint `POST /auth/telegram/consume`.
6. Backend валидирует и поглощает токен, затем устанавливает cookie `web_auth_session` (`HttpOnly`, `Secure`, `SameSite=Lax`).
7. После успешной авторизации страница загружает текущий draft через `GET /api/specialist/profile`.
8. Пользователь редактирует блоки и сохраняет их отдельными кнопками:
   - **Основное**: ФИО + специализация + цитата
   - **О себе**
   - **Образование**
   - **Услуги и цены**
   - **Отзывы**
9. Для каждого сохранения выполняется `PUT /api/specialist/profile` с merge по текущей модели на клиенте.
10. Загрузка медиа:
   - Фото: `POST /api/specialist/profile/photo` (single)
   - Документы: `POST /api/specialist/profile/documents` (multiple через последовательные запросы)
   - Список медиа для UI: `GET /api/specialist/profile/media`

## UX детали
- У каждого блока своя кнопка **«Сохранить»**.
- На успешном запросе показывается статус **«Сохранено ✅»** на ~2.5 секунды.
- При запросе кнопка блокируется до завершения.
- Текстовые поля trim-ятся на клиенте перед отправкой.
- Ошибки показываются как короткое сообщение (без stacktrace).

## Состав полей на форме
- Основное: `first_name`, `middle_name`, `last_name`, `specialization`, `hero_quote`
- Контент-блоки: `about`, `education`, `services`, `reviews`
- Медиа: фото (`photo`) и документы (`document`)
