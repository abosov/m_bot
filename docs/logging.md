# Система логирования взаимодействий (Logging System)

## Обзор
Система предназначена для детальной фиксации всех входящих и исходящих событий в экосистеме ботов. Это необходимо для аналитики, отладки и мониторинга качества обслуживания клиентов.

## Схема данных (Table: `message_logs`)

| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `id` | UUID (PK) | Уникальный идентификатор записи. |
| `created_at` | DateTime | Время фиксации события (UTC). |
| `specialist_id` | UUID (FK) | ID специалиста, к которому относится бот. |
| `bot_id` | BigInt | Telegram ID бота, через которого идет общение. |
| `tg_user_id` | BigInt | Telegram ID пользователя (клиента или мастера). |
| `direction` | Enum | `IN` (от пользователя к боту) или `OUT` (от бота к пользователю). |
| `message_type` | String | Тип контента: `text`, `photo`, `callback_query`, `document` и т.д. |
| `content` | Text | Текст сообщения или описание медиа-файла. |
| `is_error` | Boolean | Флаг, указывающий на критическую ошибку при обработке. |
| `error_details` | Text | Текст ошибки (traceback) для диагностики. |
| `processing_time` | Float | Время обработки сообщения ботом в секундах. |
| `handler_name` | String | Имя функции-обработчика (для `IN` сообщений). |

## Принцип работы
1. **Middleware**: Используется `aiogram.BaseMiddleware` для перехвата всех входящих Update.
2. **Timing**: Время замеряется с момента входа в middleware до выхода из него.
3. **Error Handling**: Если хендлер выбрасывает исключение, middleware ловит его, записывает `error_details` и пробрасывает ошибку дальше (или купирует).
4. **Outbound Logging**: Для исходящих сообщений используется перехват методов API (через middleware внешних запросов или декоратор бота).
