# UI: Блоки страницы специалиста

## Блок "О себе"
Компонент: `frontend/components/specialist/SectionAbout.tsx`.

Источник данных: `specialist_public_block` c `block_type = about`.

### Логика отображения
- Компонент ищет блок типа `about` в массиве `blocks`.
- Если блок отсутствует, секция не рендерится.
- Если текст пустой после очистки, секция не рендерится.

## Блок "Отзывы"
Компонент: `frontend/components/specialist/SectionReviews.tsx`.

Источник данных в текущем MVP: `specialist_public_block` c `block_type = reviews`.

### Логика отображения
- Компонент ищет блок типа `reviews` в массиве `blocks`.
- Поддерживается строковый контент (разбиение по строкам) и массив строк (`items`).
- Если блок отсутствует или после очистки нет непустых строк, секция не рендерится.
- `payload.reviews` не используется для рендера в текущем MVP (оставлен только для backward compatibility API-контракта).


## Блок "Документы"
Компонент: `frontend/components/specialist/SectionDocuments.tsx`.

Источник данных в текущем MVP: `specialist_public_media` (поле `media_type=document`).

### Логика отображения
- Компонент принимает массив `media` и фильтрует только элементы `media_type = document`.
- Если документов нет, секция не рендерится.
- Если у документа есть `url` (http/https), показывается кликабельная ссылка.
- Если `url` отсутствует (`null`/пусто), показывается только название документа и подсказка: «Скоро будет доступно скачивание».
- Медиа типа `photo` не попадают в секцию документов.

### Безопасность
Контент пользовательских блоков проходит HTML sanitization перед рендером:
- удаляются `<script>...</script>`
- удаляются inline-обработчики (`on*` атрибуты)
- удаляются `javascript:` из ссылок/атрибутов

Для `SectionAbout` рендер выполняется через `dangerouslySetInnerHTML` только после санитизации.
Для `SectionReviews` отзывы рендерятся как текстовые элементы списка после санитизации.
Для `SectionDocuments` в UI используются только публичные metadata (`title`, `url`, `media_type`); `file_key` не рендерится.
