## Story ID and Title

US-AUTO-60 — Implementation freeze and review-evidence refresh without Codex rerun

## Objective

Add a safe implementation-freeze path for cases where the operator has accepted the current committed implementation, but a normal fresh `run_story.sh` would invoke Codex again and risk producing non-essential polish changes.

The pipeline must support refreshing review evidence for the current committed HEAD without running Codex implementation again.

The intended operator path is:

1. implementation is accepted by the operator;
2. working tree is clean;
3. current HEAD is committed;
4. operator explicitly starts an implementation-freeze / review-evidence refresh path;
5. the pipeline creates or refreshes review-stage evidence for current committed HEAD without `codex exec`;
6. `analyze_story_run.sh` can identify the refreshed evidence as review-stage eligible;
7. `review_story_run.sh`, `ai_review_story_run.sh`, `classify_review_story_run.sh`, and `review_gate_story_run.sh` can consume that evidence through existing pinned-run / committed-HEAD safety rules.

This story exists to break the observed loop:

run_story
→ Codex adds non-essential polish
→ dirty tree
→ commit causes new HEAD and requires rerun
→ restore causes stale / fidelity blockers
→ rerun invokes Codex again
→ loop repeats

## Scope

In scope:

- introduce an explicit implementation-freeze / review-evidence refresh workflow;
- add a script or narrow command path that refreshes review evidence for the current committed HEAD without invoking Codex;
- preserve committed-HEAD and pinned-run invariants;
- make the refreshed evidence auditable and clearly marked as generated by a no-Codex refresh path;
- teach `analyze_story_run.sh` to surface the freeze/refresh path as a valid next action when appropriate;
- teach downstream review-stage scripts to accept refreshed evidence only when it is current, committed, story-scoped, and valid;
- add focused tests for no-Codex refresh behavior, stale evidence rejection, dirty-tree rejection, and downstream review compatibility;
- update operator documentation with the new freeze/refresh path;
- update registry lifecycle notes only if required by the story workflow.

The implementation should be narrow and fail-closed.

## Non-goals

Do not run Codex in the refresh path.

Do not make the normal `run_story.sh` path skip Codex by default.

Do not weaken the rule that review-stage evidence must correspond to current committed HEAD.

Do not make stale `AUTOMATION_RUN_DIR` valid after a new commit.

Do not allow refresh when the working tree is dirty.

Do not allow refresh on `main`.

Do not replace the manual-finish continuation contract.

## Current Code Reality

US-AUTO-77 added operator-facing decision output to `analyze_story_run.sh` and created `docs/90_codex/US_AUTO_OPERATOR_GUIDE.md`.

That improved operator guidance but did not solve the repeated Codex rerun loop.

Observed problem from US-AUTO-77:

- implementation was accepted;
- Codex then produced non-essential polish changes on rerun;
- committing those changes created a new HEAD and forced another rerun;
- restoring those changes could leave review artifacts stale or fidelity-blocked;
- the pipeline had no explicit way to say: implementation is accepted, do not invoke Codex again, only refresh review evidence for current committed HEAD.

The current normal safety model remains correct:

- review-stage must not consume stale evidence;
- after any new commit, old `AUTOMATION_RUN_DIR` is invalid for normal review-stage;
- dirty tree blocks review-stage;
- review/gate must evaluate the committed implementation surface, not workspace-only drift.

US-AUTO-60 must preserve these rules while adding a new explicit freeze/refresh path.

## Target Outcome

US-AUTO-60 is complete when:

1. The repo has a documented operator path for implementation freeze and review-evidence refresh without Codex rerun.
2. The implementation includes a deterministic no-Codex refresh mechanism.
3. The refresh mechanism refuses to run on `main`.
4. The refresh mechanism refuses to run with a dirty working tree.
5. The refresh mechanism records enough metadata to prove:
   - story ID;
   - current HEAD;
   - base commit or merge-base used for review evidence;
   - source run or source context if applicable;
   - no-Codex refresh mode;
   - generated artifacts.
6. `analyze_story_run.sh` recognizes valid refreshed evidence and gives a safe operator decision.
7. Downstream review-stage scripts can consume valid refreshed evidence without needing a new Codex implementation rerun.
8. Stale refreshed evidence is rejected after a new commit.
9. Dirty-tree refresh or dirty-tree review-stage remains rejected.
10. Existing manual-finish continuation behavior remains valid and unchanged.
11. Existing semantic projection / companion-filter behavior remains unchanged.
12. Targeted tests pass.

## Acceptance Criteria

- A no-Codex review-evidence refresh path exists.
- The refresh path has explicit operator invocation.
- The refresh path does not call `codex exec`.
- The refresh path is fail-closed if required committed-HEAD or diff evidence cannot be produced.
- The refresh path is fail-closed on dirty working tree.
- The refresh path is fail-closed on `main`.
- The refresh path emits metadata that clearly identifies it as no-Codex refreshed evidence.
- The refreshed evidence can be analyzed with `analyze_story_run.sh`.
- The analyzer prints an operator decision that distinguishes:
  - normal rerun required;
  - implementation-freeze refresh available;
  - refreshed evidence review-stage allowed;
  - refreshed evidence stale/blocked.
- Downstream review/classify/gate scripts either consume refreshed evidence through existing run-artifact contracts or are minimally adjusted to do so.
- Existing stale-run protections remain intact.
- Existing dirty-tree protections remain intact.
- Existing manual-finish continuation contract remains intact.
- Existing tests are not weakened.
- New tests cover the freeze/refresh path.
- The operator guide documents when to use and when not to use the new path.
