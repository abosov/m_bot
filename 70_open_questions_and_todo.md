# Open Questions & TODO (Post-MVP)

Документ фиксирует:
- решения, которые **осознанно не входят в MVP**,
- открытые вопросы,
- точки расширения архитектуры,
чтобы при дальнейшем развитии не ломать существующую модель.

---

## 1. Уведомления и напоминания (НЕ MVP)

### Не реализовано в MVP
- напоминания клиенту перед консультацией
- напоминания специалисту
- уведомления об отмене / изменении статуса записи
- email / push / WhatsApp

### Причина
- требует фоновых задач (workers, cron, queue)
- увеличивает сложность инфраструктуры
- не критично для первой версии

### TODO (Post-MVP)
- очередь задач (Celery / Sidekiq / Cloud Tasks и т.п.)
- шаблоны уведомлений
- пользовательские настройки уведомлений

## 2. Перенос записи (reschedule) (НЕ MVP)

### Не реализовано
- перенос записи клиентом
- перенос записи специалистом

### Причина
- усложняет booking state machine
- требует конкурентных блокировок
- легко заменяется: отмена + новая запись

### TODO
- добавить состояние `rescheduled`
- определить правила (>= cancel window?)
- UX для выбора нового слота

---

## 3. Конкурентная запись (race conditions) (ОГРАНИЧЕННО)

### В MVP
- нет глобальной блокировки слотов
- защита только через:
  - повторную проверку Google Calendar
  - idempotency_key
- возможны редкие гонки при одновременных кликах

### Принятое допущение
- Google Calendar — мастер занятости
- если два клиента почти одновременно выбрали слот:
  - победит тот, у кого быстрее создастся событие
  - второй получит `failed`

### TODO
- soft-lock слота в Redis
- временные блокировки (TTL)
- optimistic locking
